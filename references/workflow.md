## 6 阶段流程

### Stage 1:读题(建模手)

**目的**:识别问题数量、问题类型、数据状态。

**执行**:
1. 跑 `references/scripts/check_input.ps1` 验证 `题目/` 和 `数据/` 是否就位
2. 读 `题目/` 下所有 PDF/DOCX
3. 读 `数据/` 下所有 xlsx/csv/xlsx(全量,检查 sheet/合并单元格/多级表头)
4. 打印数据总览:每个文件的 shape/dtypes/缺失率
5. 输出:问题列表 N + 每问 1-2 句话概括 + 初步问题类型分类

**退出条件**:N 个问题 + 类型分类已确认(用户口头确认即可)。

**产出**:对话里输出(无需落盘)。

---

### Stage 2:建模(建模手)

**目的**:从整题出发,给 8 段建模思路 + 求解计划。

**执行**(顺序固定):
1. 写 `<工作区>/建模思路.md`(8 段 Markdown,bzd 风格):
   - 整题建模主线
   - 跨问题联动链(Mermaid 图)
   - 全文统一建模口径
   - 分问题求解思路(每问 4 段)
   - 全文技术路线
   - 多模型对比与验证设计
   - 论文落地清单
   - 完整性与断链检查
2. **停下来等用户拍板整体方案**
3. 用户拍板后,写 `<工作区>/求解/求解计划.md`,把抽象思路变成可执行步骤

**硬性要求**:
- 有数据题:每问 ≥1 个机器学习/统计 + ≥1 个传统机理
- 优化题:每问 ≥1 个精确算法 + ≥1 个启发式
- 评价题:每问 ≥1 个主观赋权(AHP)+ ≥1 个客观赋权(熵权/CRITIC)
- 多模型对比表中 ≥2 个真正不同的可行模型(优先 3 个)
- 创新方向必须可实现(不能是"使用 XX 算法"这种空洞说法)

**退出条件**:`建模思路.md` + `求解计划.md` + 用户口头确认。

---

### Stage 3:求解(代码手)

**目的**:用 Python 实现每个问题的建模、求解、可视化。

**执行**:
1. 创建 `求解/问题X/图片/` 和 `求解/问题X/结果/`
2. 每个问题一个 py 文件,**中文命名**(如 `问题1_影响因素.py`)
3. **先算后画**:计算完成 → 打印 min/max/mean/std → 再画图
4. 每题至少 **4-6 张图**,覆盖主要分析维度
5. 问题 1 必须输出 `求解/预处理数据.csv` 供后续共用
6. **灵敏度分析前置**:求解阶段就测关键参数影响
7. 脚本报错 → 修复 → 重跑,通过后再下一问

**公共头部**:见 `references/code-template.py`(含 `save_csv` 函数)。

**图规范**(从 scipilot-figure-skill 集成,15 条避坑):
- 用模板自带的 rcParams 预设(基础 14pt / 标题 16pt / 轴标签 14pt / 刻度 12pt)
- 图宽度 9 英寸(适合 A4 单栏)
- 一图一论点,n<10/组不画均值柱、不用双 Y 轴、不用饼图、不用 rainbow 色图等

**退出条件**:所有 py 运行无错 + 每题 ≥4 张图 + 问题 1 输出 `预处理数据.csv`。

---

### Stage 4:写作(论文手)

**目的**:按 11 个 .tex 写论文,严格遵守硬规则。

**章节命名**:见 `references/chapter-structure.md`(单一来源,不要复制此表)。

**5.x 子节结构**:每个问题 5 个子节(5.X.1 数据预处理 / 5.X.2 建模 / 5.X.3 求解 / 5.X.4 检验 / 5.X.5 结果分析),详见 chapter-structure.md。

**写完后逐项自检**:跑 `py -3 references/scripts/auto_verify.py <工作区>` 机械检查 + 人工对照 `references/eval-checklist.md` 的 D 节(完整性) + C 节(硬规则) + F 节(2026 规范)。

**退出条件**:全部 .tex 写完 + auto_verify 全 PASS + 人工 review 关键硬规则。

---

### Stage 5:验收(验收手)

**目的**:对照 `references/eval-checklist.md` 逐项检查。

**执行**:
1. 跑 `references/scripts/auto_verify.ps1` 自动跑机械检查(A 编译层 + C 硬规则 + D 完整性)
2. 手动检查 B 数值一致性 + E 模型合理性 + F 2026 规范
3. 跑 `references/scripts/build.ps1` 编译两份 PDF
4. 跑 `references/scripts/check_input.ps1` 二次验证(支撑材料是否齐)
5. 输出验收报告:每项 PASS/FAIL,FAIL 指出文件:行

**通过条件**:
- A1-A4、A6-A7、A11 必须 PASS(编译 + PDF 存在 + 无目录)
- C 全部 PASS,允许 1-2 项 FAIL
- D1-D3、D7、D8 必须 PASS
- E 允许 2 项 FAIL
- F.1 和 F.2 全部 PASS,F.3 允许 1 项 FAIL,F.4.1-F.4.5 必须 PASS

**回退**:
- 全部 PASS → 进 Stage 6
- 1-3 项 FAIL → 修补后重跑验收
- >3 项 FAIL → 退回 Stage 4 重写对应章节

---

### Stage 6:出 PDF(验收手)

**目的**:编译三份 PDF(纸质版 + 电子版 + AI 详情)。

**执行**:
1. 跑 `references/scripts/build.ps1`(自动编译三份 PDF):
   - `论文.tex` → `论文.pdf`(纸质版,含承诺书+编号页)
   - `电子版.tex` → `电子版.pdf`(电子版,跳过前两页)
   - `AI工具使用详情.tex` → `支撑材料/AI工具使用详情.pdf`(如果存在,自动复制到支撑材料目录)
2. 验证三份 PDF 存在:
   - `Test-Path 论文/论文.pdf`
   - `Test-Path 论文/电子版.pdf`
   - `Test-Path 支撑材料/AI工具使用详情.pdf`(如果填了 AI 详情)
3. 检查页数(纸质版 25-50 页,电子版比纸质版少 2 页)
4. 检查 PDF 大小(电子版 ≤ 20MB,2026 规范第十条)
5. 报告交付:PDF 路径、页数、字数估算、最后修改时间

**AI 详情 PDF 工作流**(2026 AI 规定第 4 条必交):
- 模板:`论文/AI工具使用详情-template.tex`(对应 `.md` 版,内容一致)
- 填写:复制为 `AI工具使用详情.tex`,填【】占位符
- 编译:`build.ps1` 自动跑(集成在末尾)
- 输出:自动复制到 `支撑材料/AI工具使用详情.pdf`
- 单独编译:`pwsh -File references/scripts/build_ai_detail.ps1`

**退出条件**:三份 PDF 存在且能打开 + 页数符合预期。

## 快速模式分支(跳级)

| 用户说 | 跳到 | 跳过 |
|--------|------|------|
| "只写论文" / "跳过求解" | Stage 4 | Stage 1-3(假设 求解/ 已就绪) |
| "只跑代码" / "求解" | Stage 3 | Stage 1-2(假设 求解计划.md 已就绪) |
| "只验收" / "检查" | Stage 5 | Stage 1-4(假设 论文.tex 已就绪) |
| "只出 PDF" / "编译" | Stage 6 | Stage 1-5(假设 论文.tex 已就绪) |
| "改 XX" / "改这一章" | 局部修改 | 走 build.ps1 编译 |
| "改格式" / "改排版" | 局部修改 + 编译 | 调 format.cls 后走 build.ps1 |

快速模式 = 跳到对应阶段 + 跳过上一阶段产物检查(用户自担保)。

## Stage 间的回退与并行

### 回退规则

| 当前 Stage | 失败 | 回退到 |
|-----------|------|--------|
| Stage 1 | 题目/数据缺失 | 停下等用户补齐,不回退 |
| Stage 2 | 用户不拍板 / 求解计划太粗 | 停在 Stage 2 反复推敲 |
| Stage 3 | 某题求解失败 | 修该题 py,不上溯 Stage 2 |
| Stage 4 | 某章 .tex 写完自检 FAIL | 修该章,不上溯 Stage 3 |
| Stage 5 | 编译失败 | 修 .tex(Stage 4 产物),不上溯 Stage 3 |
| Stage 5 | 数值不一致 | 改论文 + 改代码(Stage 3 产物) |
| Stage 5 | 硬规则违规 | 改论文(Stage 4 产物) |
| Stage 6 | 编译失败 | 回 Stage 5(同一本质) |

### 并行规则

- **Stage 3 各题之间**:可以并行(分别在不同子目录),但 Stage 3 整体必须等所有题完成才能进 Stage 4
- **Stage 5 + Stage 6**:Stage 6 包含在 Stage 5 末尾的 build.ps1 中(顺序执行)
- **其他 Stage**:严格顺序

## 论文核心规则(硬规则速查)

> 详细规范见 `references/paper-spec.md`(各章字数/结构/写作模板)。
> 章节命名见 `references/chapter-structure.md`(单一来源)。

### 禁止事项(违反即扣分)

| 禁止 | 例外 |
|------|------|
| 正文分点符号(①②③、●○、1.2.3.) | 模型假设/评价的 itemize |
| 正文加粗 `\textbf{}` | 摘要"对于问题X"、问题重述"问题N:"、假设/优缺点头部 |
| 全文 `\newpage` | 仅参考文献和附录前可用 |
| 图上 `set_title()` | 标题由 `\caption{}` 承担 |
| 表格换行 | 格子文字一行显示 |
| 摘要超 1 页或含公式 | — |
| 目录 `\tableofcontents` | 2026 规范第四条:论文不要目录 |

### 图表规范

- 图宽 `0.8\textwidth`,表宽 `\textwidth`
- 所有表格统一 `longtable` + `>{\centering\arraybackslash}p{}`
- caption/label 格式:`\caption{...}\label{tab:xxx}\\`,caption 在 label 前
- 图文件通过相对路径引用:`../求解/问题X/图片/xxx.png`

## 常见错误(求解和写论文时主动避开)

1. ❌ 公式堆砌无串联 → ✅ 每个公式前后有中文过渡句
2. ❌ 变量无说明 → ✅ 每个公式后跟"其中,$X$表示..."
3. ❌ 表格用 `tabular`/`tabularx` → ✅ 统一 `longtable` + `p{}`
4. ❌ 图上写标题 → ✅ 标题放在 `\caption{}`
5. ❌ 图表无引用 → ✅ "如图X所示""如表X所示"
6. ❌ 分点符号 → ✅ 自然段落
7. ❌ 摘要超页 → ✅ 编译后验证,超了就缩减
8. ❌ 参考文献无引用 → ✅ 每条 `\bibitem` 对应正文 `\cite`
9. ❌ 优化模型只写文字 → ✅ 完整写出目标函数+约束+变量
10. ❌ 模型检验缺失 → ✅ 6.1 误差 + 6.2 灵敏度 + 6.3 稳健性
11. ❌ 用 1.引言/2.总体分析 等老章节名 → ✅ 用 1.问题重述/2.问题分析(v3 命名)
12. ❌ 5.X 只有 5.X.1+5.X.2 → ✅ 5.X.1-5.X.5 五个子节(v3 拆分)
13. ❌ 保留 8.章 → ✅ 已删除,改进并入 7.3
14. ❌ 公式直接 `\begin{equation}` → ✅ 加 `\label{eq:xxx}` 便于引用
15. ❌ 代码不输出 `预处理数据.csv` → ✅ 问题 1 必须输出
